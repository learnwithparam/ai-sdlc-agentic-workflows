# Parts: the plan for each part session

For course authors. One part session builds one part from this file alone. Read `STANDARD.md`, then the brief on `research/ai-sdlc-agentic-workflows` in the curriculum repo, then the part's README, which already has the problem, the cited number, the diagram and the step table.

## How a step is built here

- The learner writes no code. A step's challenge is a job to give Claude Code.
- `problem/` and `solution/` and each `wrong/<mistake>/` hold only the files that differ from `world/kestrel/`. `checks/lib/snapshot.ts` lays them over the base world, so a check always reads a whole Kestrel repo. `bun run start <step>` and `bun run catch-up <step>` do the same into `kestrel/`.
- `problem/` is the begin state: the end of the step before, plus anything the step plants. `solution/` is the end state plus `prompts.md`: the prompts, the plan Claude showed, what to check, what to reject. `scripts/check.ts` fails a `solution/` with no `prompts.md`.
- A snapshot whose check reads git history ships `history.bundle` (`git bundle create history.bundle --all`). The snapshot is then a clone of the bundle with the folder's files laid on top. `world/finished/history.bundle` is an example.
- Make every end state with a real Claude Code run, and keep its transcript, as `parts/01-ready-the-repo/` does. Redact model names with `withoutModelNames` in `checks/lib/recordings.ts`. List each run in `world/recordings/RECORD.md`.
- Steps that need a headless run add it to `RECORDED_RUNS` in `config/claude-code.ts`, so `bun run record <step>` works.
- Gates use `bun run approve <file> --role <role>`; checks use `approvalHolds` and `approvedInOrder` from `checks/lib/approvals.ts`. The chain order is `checks/lib/chain.ts`.
- The world contract (feed and queue) is `checks/lib/world.ts`. The finished end state of every file is in `world/finished/`; a part's last `solution/` should match it.
- When a part is built, remove `TODO(part session)` from its README, write the Walkthrough with an `Expect:` line per command, and add the part's steps to `scripts/shots.ts` if any has `screen = true`.

## Planted faults already in the world

- `src/wrenches.ts`: a wrench never sets `is_disabled`, so the bike stays rentable in the feed.
- `src/crew-queue.ts`: the queue is oldest first, and the deadline clock runs from `opened_at`, not the wrench.
- `data/`: 56.8% of late bikes are e-bike battery faults at North depot stations. "More crews" is the wrong answer.
- `world/incidents/north-double-wrench/`: the incident logs for Part 7. Copy them into Part 7's `problem/` as `data/incidents/north-double-wrench/`.
- Part 5's planted clock-change branch is not built yet: the part session plants it in `problem/` with a `history.bundle`.
